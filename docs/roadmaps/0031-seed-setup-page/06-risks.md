# 0031 · Risks worth naming before starting

- **0031.2 discards a database with real-looking state.** The dev database holds 111 users, 181 role rows, 5 TSK curations, 265,807 LXX tags and 12 invite codes — none of it comes back from a seed. The backup is the renamed bind-mount folder `temp/postgres-data.before-0031`, so it is only as good as the shutdown: rename it only after `docker compose down` has stopped Postgres cleanly, never while it runs, and start it once in a throwaway container to count; that check is the "done when" of 0031.2, not a formality. The folder sits under `temp/`, which also holds the download cache: never clean `temp/` wholesale while the backup is wanted.
- **From 0031.3 to 0031.6f the stack has no seed path except the CLI.** Anyone who pulls in that window gets an empty app and a fake page. Keep the window short (no other feature work in between) and say so in the index status; `compose.fresh.yml` plus the SeedDb CLI is the fallback.
- **Steps that are not resumable turn a timeout into a stuck amber row.** `ElberfelderTextRunner` has no skip check; a run that dies after half the 722,743 words leaves rows that block a re-run, and this roadmap has no "Leeren". Mitigation: the 900 s command timeout in 0031.6, a transaction per step where the runner allows it, and a manual `TRUNCATE` note in the log. If amber rows happen more than once, "Leeren und neu importieren" is the next roadmap.
- **Caches keep the empty state after a seed.** `SourceFormIndex` holds its snapshot for 30 minutes, `StrongsLexiconIndex` and `SttsDriftCheck` read once; without `ISeedDataChanged` (0031.6) the reader shows "unbekanntes Wort" or no lexicon right after a green seed. Every newly wired group must be checked for further caches when its runners move.
- **Separate jobs break the implicit `StepImportResult` coupling.** Today the edition refresh and the verse-similarity rebuild run only because the same process just inserted words. If the catalog's "when the table is empty" rules are wrong, editions or similar verses stay empty on a page-seeded database while CLI-seeded ones look fine — only the end-to-end row 0031.10 on a second empty database proves it.
- **Long downloads inside the API process.** The STEP and LXX steps download hundreds of MB into `temp/` from the API container, which now needs outbound internet and write access (`1000:1000`, already set). A container restart mid-download kills the job; the counts stay honest, but a partial download file in `temp/` may be reused. Check the downloaders' "already cached" logic when they move (0031.7).
- **Unpopulated materialized views were invisible until now.** Five of six are unpopulated on the dev database; pages that read them may have been broken quietly. 0031.9 makes the state visible; it does not audit which pages depend on them.
- **The Admin-only rule rests on the first-account bootstrap.** If `REGISTRATION_MODE` is `Restricted`, the first registration must still be admitted (`Admission` lets the first account through). Test it once in 0031.3 with `REGISTRATION_MODE=Restricted`.
