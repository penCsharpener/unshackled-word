### Group card (`SetupGroupCard`, page-local)

- `<section aria-labelledby>` card; header row `flex flex-wrap items-center justify-between gap-2`: `h2.text-lg.font-semibold` with the group label, a muted source hint (`setup.source.*`: steps of the group share one source; `step` = "Download, braucht Internet"; a mixed group, `other`, shows no group hint but a per-row hint), and "Gruppe ausführen".
- "Gruppe ausführen" is disabled when a job runs or when the group has no runnable step (`runnableKeys(group).length === 0`); its `title` names why (`setup.groupNothingToRun`).
- Rows as `<ul className="flex flex-col divide-y divide-border">`.

### Step row (`SetupStepRow`, page-local)

- `<li className="flex flex-wrap items-start gap-x-3 gap-y-1 py-2">`
  - line 1: dot (see proposals) + label `font-medium` + optional source hint (`text-sm text-fg-muted`) for mixed groups, and "(aus Migration)" for `books`.
  - line 2 (`basis-full pl-6 text-sm text-fg-muted`): the **status word** (`setup.status.<status>`, so the dot is never the only carrier), then "braucht: Elb1871-Text, Bibelbücher" for grau (labels of `missing`, not keys), then tables `Name 722.743` separated by middots; table names in `font-mono` and `break-all` so long names wrap at 375 px.
  - button "Ausführen" `ml-auto`; read-only rows (`runner === null`, `books`) show no button. Disabled when: status `green` ("schon fertig"), `grey` ("braucht: …"), `amber` and not `resumable` ("teilweise gefüllt, nicht fortsetzbar"), `wired === false` (label "noch nicht angebunden"), or any job runs. The reason goes into `aria-describedby` → line 2, so a screen reader hears why.
  - running step: dot pulses (`busy`), status word "läuft …".
  - failed step (amber via `failed` flag): status word "fehlgeschlagen", plus the last 3 log lines of that job in `font-mono text-sm` under line 2.

### Header

- "Alle ausführen" `primary`: disabled while a job runs or nothing is runnable; when everything is green it reads "Alles fertig" and stays disabled.
- Status line `role="status"`: `setup.stand` ("Stand: {{time}} · {{done}} von {{total}} Schritten fertig"), time via `toLocaleString(i18n.language, { dateStyle: "short", timeStyle: "short" })`. While running it adds " · läuft: {{step}}".
- Refresh `ghost sm` (↻ svg, `aria-label={t("setup.refresh")}`) refetches the status; disabled while fetching.

### Job log (`SetupJobLog`, page-local)

Same markup as the `SeedImportsPage` job card. Heading: `setup.job.title` with step label (or group / "Alle") and elapsed `mm:ss` (ticks with the 2 s poll, no own timer). `details` open while running or failed, closed after success. Shows the last 500 lines (the fake keeps 500). Under the log after a chain run: "Gestoppt bei: {{step}}" when the chain stopped at a failure.

### States

| State | What shows |
|---|---|
| auth loading | `RequireRole` renders nothing |
| anonymous / not admin | redirect to `/login` / `admin.forbidden` note (`role="alert"`) |
| loading | `h1` + `<p role="status" className="text-fg-muted">{t("setup.loading")}</p>`, no cards |
| load error | `FormError` with `describeApiError` + secondary "Erneut versuchen" |
| empty catalog | `EmptyState title={t("setup.emptyCatalog")}` (defensive) |
| idle | cards; red rows runnable, grau rows disabled with "braucht: …" |
| running | all run buttons disabled; running row pulses; job card visible and polling every 2 s; counts of a finished step appear when its sub-job ends (chain = several steps in one job, the rows turn green one after another) |
| failed | job card heading status "fehlgeschlagen" + `role="alert"` error; failed row amber with "fehlgeschlagen" and last lines; chain stops, header says `setup.stoppedAt` |
| done | header "22 von 22 Schritten fertig", "Alle ausführen" disabled as "Alles fertig", job card collapsed log |
| 409 / 400 from run | `FormError` under the header (fake can only produce these by a race; kept so 0031.5f needs no layout change) |

### 375 px and dark mode

- `p-4` = 16 px gutter; header and group headers `flex-wrap`, so buttons drop under the title; row button stays on line 1 (`ml-auto`), line 2 is full width; table names `break-all`; log `overflow-x-auto` with `whitespace-pre` lines inside its own box (no page scroll).
- Tokens only: `bg-surface`, `border-border`, `text-fg`, `text-fg-muted`, `text-accent` for errors (as `SeedImportsPage`), `bg-sev-ok|warning|error|info`, `bg-fg-muted` for grey. The `--uw-sev-*` values are defined in both themes, so dark mode needs nothing extra. Pulse only under `motion-safe:`.

export type SetupGroup = "base" | "step" | "other" | "derived";

/** Derived by the server from row counts (03-seed-catalog.md, status rule). */
export type SetupStepStatus = "green" | "amber" | "red" | "grey";

export interface SetupTable {
  name: string;
  rows: number;
  /** Materialized views (stats-views): populated yes/no before a count makes sense. */
  populated?: boolean;
}

export interface SetupStep {
  key: SetupStepKey;
  group: SetupGroup;
  source: SetupSource;
  /** Host for the "needs internet" hint, download steps only. */
  sourceHost?: string;
  status: SetupStepStatus;
  requires: SetupStepKey[];
  /** Requires that are not green; non-empty exactly when status is grey. */
  missing: SetupStepKey[];
  resumable: boolean;
  /** false until the runner has moved into UnshackledWord.Seeding (0031.5–0031.8). */
  wired: boolean;
  /** false for read-only rows (books from migration 0001). */
  runnable: boolean;
  /** A job for this step failed in this API process (makes it amber). */
  failed?: boolean;
  /** Valid green with 0 rows ("nichts zu importieren"): revision-seed, lxx-tags links. */
  note?: "nothingToImport";
  tables: SetupTable[];
}

export interface SetupStatus {
  checkedAt: string;
  steps: SetupStep[];
  /** Same shape as api/maintainer/seed/status; operation "setup", kind = step key | `group:<g>` | "all". */
  job?: SetupJob;
}

/** SeedJob widened by the setup operation; 0031.5f adds "setup" to SeedOperation and drops this alias. */
export type SetupJob = Omit<SeedJob, "operation" | "kind"> & {
  operation: "setup";
  kind: SetupStepKey | `group:${SetupGroup}` | "all";
  /** Step currently running inside a group/all job. */
  currentStep?: SetupStepKey;
  /** Step that failed and stopped the chain. */
  failedStep?: SetupStepKey;
};

export type RunSetupRequest = { keys: SetupStepKey[] } | { group: SetupGroup } | { all: true };

export const SETUP_STEP_KEYS = [
  "books", "stts", "revision-levels", "elb1871-text", "elb1871-verses",

  "morphology", "tsk", "tsk-curation", "sr-gnt", "sbl", "ai-mappings", "lxx-text", "lxx-tags", "revision-seed",
  "verse-similarity", "stats-views",
] as const;
export type SetupStepKey = (typeof SETUP_STEP_KEYS)[number];
export const SETUP_GROUPS: readonly SetupGroup[] = ["base", "step", "other", "derived"];

## The fake (`lib/setup/setupFake.ts`)

```ts
/** Dev counts from 03-seed-catalog.md, in catalog order. 22 entries. */
export const FAKE_CATALOG: readonly FakeStepSpec[];
interface FakeStepSpec {
  key: SetupStepKey; group: SetupGroup; source: SetupSource; sourceHost?: string;
  requires: SetupStepKey[]; resumable: boolean; runnable: boolean;
  tables: { name: string; rows: number; populated?: boolean }[];   // target counts after "run"
  note?: "nothingToImport";
}

export interface FakeOptions {
  /** ?fake=reset: clear the stored state before the first read. */
  reset?: boolean;
  /** ?fake=fail:<key>: that step fails once (exercises the failed state at Gate A). */
  failKey?: SetupStepKey;
  /** Injectable for tests. */
  random?: () => number;
  now?: () => Date;
}

/** Reads `?fake=` from the URL (comma list: `reset`, `fail:<key>`). */
export function fakeOptionsFromSearch(search: string): FakeOptions;

export interface SetupFake {
  status(): Promise<SetupStatus>;
  /** Rejects with ApiError(409) while a job runs, ApiError(400) naming a key that is not runnable. */
  run(request: RunSetupRequest): Promise<SetupJob>;
  /** Clears state and timers (tests, ?fake=reset). */
  reset(): void;
}
export function createSetupFake(options?: FakeOptions): SetupFake;
/** Module singleton used by useSetup.ts; created on first use with fakeOptionsFromSearch(location.search). */
export function setupFake(): SetupFake;
```

Behaviour:

- **Start state:** every table 0 except `books` (`BibleBooks` 66, `Languages` 2) → 1 von 22 fertig, everything with `requires: ["books"]` red, the rest grey.
- **Values:** `revision-seed` targets 0/0/0 with `note: "nothingToImport"` (green); `lxx-tags` `LxxHebrewLinks` 0 is fine because `LxxWordTags` > 0 (green rule per step uses the note: a step with `note` is green when its non-noted tables have rows). `stats-views` tables carry `populated`. `step-lexicon` lists only `StepStrongsLexicon` (the empty person/place/other lexicons are left out of the fake; decide at Gate A whether the real row lists them).
- **Run:** `run` validates with `runnableKeys`, creates a job `{ id: crypto.randomUUID(), operation: "setup", kind, status: "running", startedAt, log: [] }` and walks the planned keys: per step a duration of `1500 + random() * 2500` ms, a log line every 300 ms from `fakeLogLines(step)` (template per source: `"{time} {key}: lade {host}…"`, `"… {n} Zeilen gelesen"`, `"… {table}: {n} eingefügt"`, `"{key}: fertig ({s} s)"`), then sets that step's tables to the target counts. `currentStep` follows the walk. On `failKey`: after half its duration the step gets half of its first table's rows (→ amber), `failed: true`, job `status: "failed"`, `error: "Fake-Fehler in {key}"`, `failedStep`; the chain stops. `failKey` triggers once per stored state.
- **Persistence:** state (`counts`, `failed`, `job`, `failConsumed`) in `sessionStorage` key `uw.setup.fake`, every access in `try/catch`; without storage it is in-memory only. A reload during a run marks that job `failed` with `error: "Seite neu geladen"` (timers do not survive), mirroring an API restart.
- **Time:** all timers via `setTimeout`, so tests use `vi.useFakeTimers()`.

## Component proposals

**Status dot – needs the maintainer's yes before 0031.1 starts.** No existing component draws a small round status mark: `StatusBadge` is a bordered label with an icon and text, `StatTile` is a card, `ProgressBar` a bar. Two options:

**A (recommended): variant on `StatusBadge`** – new prop `variant?: "badge" | "dot"` (default `badge`) and `busy?: boolean`.
- `dot`: `<span data-tone className="inline-block size-2.5 shrink-0 rounded-full bg-sev-<tone>">` (`neutral` → `bg-fg-muted`, `info` → `bg-sev-info`) with `{children}` in an `sr-only` span; `busy` adds `motion-safe:animate-pulse` (running step).
- Mapping on this page: green → `ok`, amber → `warning`, red → `error`, grey → `neutral`, running → `info` + `busy`.
- Why a variant fits: same tones, same token set, same "text carries the meaning" contract (the text is sr-only in the dot and the row prints the status word visibly next to it), one entry in `Components.md` gets one sentence more. Existing badge callers are untouched.
- Cost: `StatusBadge`'s doc line ("never colour alone") must say that the dot variant relies on a visible status word next to it.

**B: new component `StatusDot`** (as 04-setup-page.md suggested) – props `tone: StatusTone`, `label: string` (sr-only), `busy?: boolean`. Only worth it if the maintainer wants the badge kept strictly as a text label; otherwise it duplicates the tone table of `StatusBadge`.

**C: no dot at all** – use `StatusBadge` (badge variant) with the status word as the row's marker ("✓ fertig", "▲ teilweise gefüllt", "✕ leer", "• wartet"). No component change, but the rows get noisier and the sketch in 04-setup-page.md loses its dots.

No other new component: group card, step row and job log are page-local functions in `SetupPage.tsx`. If the job log is wanted on a second page later (0031.5f "Wartung" link), extract it then as `SeedJobLog` (proposed then, not now).
