# 0026 · Risks worth naming before starting

- **This may duplicate 0018 rather than extend it.** The main mapping already has a morpheme column, a rule backfill and morpheme-aware prompts; they were simply never applied to the live data. If the shadow rules run (0026.3) already reaches the accuracy bar, the cheapest outcome is to run the 0018 backfill and drop the layer. That is a valid result, and the gate lists it as an option on purpose.
- **Two sources of truth for morphemes.** While both exist, the reader could show a morpheme assignment that disagrees with the main mapping's `StrongsNumber` (after a backfill). The toggle stays maintainer-only until the gate, and 0026.7f lists every such conflict, so readers never see two answers.
- **Confident nonsense from the AI pass.** A wrong suffix assignment looks plausible (*ihr* vs *sein* on H9023/H9033). The validator only checks structure, not meaning. Mitigation: nothing reaches public readers before the gate, accuracy is measured on a frozen reference set, and `human` rows can never be overwritten by a machine run.
- **Position vs. Strong's mismatch at promotion.** Words with a repeated Strong's (two ל pieces, `#n` instances) keep two positions in the layer but only one Strong's in the main mapping. The promotion report lists them; they stay with the maintainer instead of being guessed.
- **STEP data revisions shift positions.** The layer keys on `StepHebrewWords.Id` and piece position. A re-import of STEP with changed segmentation would leave rows pointing at the wrong piece. The SeedDb runs only on initial startup, so this cannot happen silently today; if STEP is ever re-imported, the layer must be rebuilt (the projection and rules producers are free to rerun; the AI and human rows are the loss).
- **Cost of the AI pass over the whole OT.** About 23,000 verses; 0026.6 measures cost per verse on a small range before anyone decides on more. No full-OT run is part of this roadmap.
- **Assumption: the live DB state is unknown.** The numbers in [01-goal.md](01-goal.md) come from the dev DB (no link-role backfill applied). If the live DB already has 0018 morphemes, the projection producer covers most words and the plan shrinks to evaluation plus the reader view.
