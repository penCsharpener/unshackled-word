# 0021 · Risks

- **The monitoring stack competes with the app for RAM on one host.** otel-lgtm needs roughly 1–1.5 GB, Umami about 200 MB, Kuma about 100 MB. On a 2 GB VM, Postgres and the API get squeezed and the monitoring itself causes the outage it should report. Check free memory before 0021.11. If the host is small, run only Kuma and Umami there and leave out otel-lgtm until there's more RAM.
- **Grafana on a public subdomain is a new attack surface.** A weak admin password or anonymous access left on exposes SQL panels and the trace search. Mitigation: strong password from `.env`, anonymous and sign-up off, pinned image updated with the others (security checklist). The `uw_grafana` role limits the damage to aggregated views.
- **Logs and traces become personal data with a retention duty.** Shortened IPs from the rate limiter, user ids in log properties, and URLs with search terms (`?q=`) end up in Loki and Tempo. Without the 14-day retention in 0021.11 they are kept indefinitely. Check whether search routes carry the query in the path. If they do, drop the query string from `url.full`/`url.query` in the AspNetCore enrichment.
- **The DB restart for `pg_stat_statements` is a short outage.** Changing `shared_preload_libraries` restarts Postgres, and the API returns 503 for a few seconds. Do it in a quiet minute. The guarded migration means skipping it is harmless.
- **otel-lgtm may not take a custom collector config cleanly.** The image is built for demos. If mounting the scrape job for postgres_exporter (0021.6) or the retention configs (0021.11) fights the image, switch to separate `grafana`, `prometheus`, `loki`, `tempo` containers. That changes compose and provisioning paths but no app code.
- **A compose `healthcheck` on the API is not possible yet.** The `aspnet:11.0` image has no curl/wget. Kuma checks from outside, which covers alerting. A compose-level `condition: service_healthy` for the API (e.g. for the proxy) needs a small health-probe binary or a chiseled image with a probe. Deferred.
- **Analytics can miscount and nobody notices.** If `uwBeforeSend` misses a staff route, maintainer clicks inflate reader numbers. If DNT and ad blockers are common among readers, numbers run low. Treat Umami as a trend, not as truth. The Vitest cases for the exclusion list must grow when new maintainer routes are added.
- **Alert mail goes through the same SMTP account as login links.** A flood of alerts can hit provider sending limits and delay magic-link and password-reset mails. The rules have a minimum request count and a 10-minute window. Use a different sender if the provider allows it.
- **Frontend errors stay invisible (deliberately deferred).** A React crash that never calls the API leaves no trace on the server. Signal to start GlitchTip: a reader reports a blank page that has no 5xx in Loki at that time.
- **Telemetry costs per request are untested at this scale.** Expected to be negligible (BatchExporter, sampling 1.0). If p95 rises noticeably after 0021.1, lower `TraceSampleRatio` before removing instrumentation.
