# 0024 · Risks worth naming before starting

- **The key moves when the counting map moves.** Curations are keyed by Elberfelder `HebRefId`s derived from `BibleVerseCountingMapping`. If that mapping changes after curation started, some `origin = tsk` keys no longer match a `Tsk` row and silently vanish from the reader. Mitigation: the import reports such keys as skipped, and a data-quality check "TSK-Kuratierung ohne TSK-Zeile" counts them; run it after every counting-map change.
- **The 0044 backfill must equal today's read path exactly.** If the SQL normalisation differs from `CrossReferenceMapper` in one edge case (backward ranges like Heb 9,21-15, cross-chapter ranges), readers see changed lists and curations attach to the wrong key. Mitigation: 0024.2's before/after comparison runs over whole books, not samples, and the C# mapper stays as the single source until the comparison is green.
- **Hiding teaches by omission.** A wrong "hide" removes a reference from every reader without any visible trace, which is worse than a missing highlight. Mitigation: only maintainers hide directly, hidden refs stay visible greyed in curate mode, every change is in the audit, and "Exakt wie Datei" import asks before deleting.
- **Comments become a second notes system.** 500 plain-text characters per link is deliberately small; if curators start writing essays there, the answer is linking a public note (0023), not raising the limit or adding Markdown.
- **Word links drift with every Elb1871 text edit.** Positions are Elb1871 positions; a rebase or a lemma fix that changes `WordInContext` drifts links to verse level. That is the safe failure, but nobody is told. Signal to act: the drift count in data quality grows; then add a re-link list like notes' "Neu verankern".
- **Manual linking does not scale to 306,000 refs.** Most refs will stay "Ohne Wort" for a long time, so the word box keeps showing verse-level lists. That is accepted (decision 2026-11-23); automatic linking is the deferred follow-up.
- **The seed file is public.** `assets/seed/tsk/curations.csv` ships in the repo; it must never contain user ids, emails or names. The 0024.7 "Done when" checks this; keep it in the export test.
- **Drag and drop on top of the existing word selection (0023).** The reader already has drag-to-select for notes. In link mode the word buttons are drop targets and the notes selection must be off, or a drag starts a note selection. 0024.5f must test both modes on the same page.
