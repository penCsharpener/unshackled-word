## Status (2026-11-27)

Implementation on `feature/vocab-roots` (uncommitted).

- **0030.1 done (0.15.0, migration 0056).** `HealthChecks.ExpectedMigration` raised to 56 (57 since 0030.4).
- **0030.1f done (0.15.1).** The Strong's link goes to the root entry when it is on the page, otherwise to the list searched for the root lemma (there is no client lookup from key to entry). Columns sit between Lernform and Bedeutungen.
- **0030.2/2f done (0.15.2).** Dev DB: 1,025 Greek compound rows (below the planned ≥1,200; 478 hyphenated headwords stay unresolved: ~250 root not a lexicon lemma, ~226 non-preposition first part such as ἀ-/εὐ-/ἀρχι-, 6 ambiguous) and 1,511 Hebrew/Aramaic verb rows (1,333 `H:V` + 178 `A:V`). A second run writes 0. The root text is the vocab `Lemma` (πορεύω, not πορεύομαι). The preposition table has 17 entries (ἀμφί has no Strong's). Status counts come from a separate `api/maintainer/vocab/roots/status`. SeedDb runs the prefill inside the `vocab-generate` verb, plus its own verb `vocab-roots-prefill`.
- **0030.3/3f done (0.15.3).** `root` + `subRoots` on both list endpoints (own entry first, then rank; a root's own entry counts as a member even without its own simple-word row, because the prefill writes no simple rows), `missingRoot` in the editor list, `GET api/vocab/roots/{id}`, `root` on the entry detail. Frontend: root text links to the family, `VocabFamilyFilter` (chip, "mit Unterwurzeln", "↑ parent"), filter "Ohne Wurzel", "Wortfamilie" block on the detail page. Sub-roots are not grouped visually, they sort by rank like the rest.
- **0030.4/4f done (0.15.4, migration 0057).** Agent mode `vocab-root`: `VocabRootRunService`/`VocabRootRunExecutor` (Infrastructure/Vocab), `VocabRootAnswerValidator` + `VocabRootPackage` (Application/Features/Vocab/Roots), prompts `vocab-root-greek-v1.md`/`vocab-root-hebrew-v1.md`, endpoints `api/maintainer/vocab/root-runs` (estimate, start, `{runId}/report`). The option "Vorbefüllung prüfen" is stored in the run's existing `IncludeConfirmed` column. The run report is the table `VocabRootRunItems` (migration 0057: rejected, flagged, replaced per run). Beyond the spec: a `low` confidence answer is flagged, not written; a root other than the word without prefixes is flagged (it does not concatenate); Hebrew accepts `simple` as "own consonants". Frontend: `pages/VocabAgentRunCard` is the shared run card of the form and root run in the vocab jobs section (`kind` prop), the root run adds the option switch and the report with `/edit/vocab/{id}` links. Verified with a stub model (no live run, see the report of the task).
- **0030.5/5f done (0.15.5, migration 0058).** `VocabEntryChanges_Kind_CK` allows the kind `root`; `VocabChangeService` leaves it out of the learners' change list. `VocabRootEditor` (Infrastructure/Vocab): `PUT api/maintainer/vocab/entries/{id}/root` (simple, prefix keys + root id or Strong's key, Hebrew letters + optional verb key + homograph; checked by `VocabRootAnswerValidator`, which also refuses a flagged answer, so an implausible concatenation cannot be saved manually; row `manual`, change row `root` at the current version, no bump) and `PUT api/maintainer/vocab/roots/{id}/parent` (body `parentRootId` or, for a Greek word without a root row, `parentStrongsKey`; refuses another track, itself, cycles with the path in the message, and more than 4 levels; none of both clears it; returns the family card). Helpers: `GET api/maintainer/vocab/roots/prepositions` and `.../roots/search?track=&q=` (Greek: entries by lemma prefix with the root row of their key, Hebrew: roots by letters); the editor entry response carries `root` (prefix keys, homograph, ancestors). Frontend: `pages/vocab/RootSection` + `RootSearch` on `VocabEditorPage` (no new shared component). The root save is disabled while the page has unsaved changes, because the reload after a save drops the draft.
- **0030.6/6f done (0.15.6).** Root on `VocabCardResponse` (not `Application/Features/Vocab/VocabCard`, which is scheduling state), only for non-simple roots; shown on the introduction card and in the answer feedback, never on the front.
- **0030.7/7f done (0.15.7).** `assets/seed/vocab/roots.csv` (1,977 roots) and `word-roots.csv` (2,538 word rows) written by `VocabSeedExporter`, read by `VocabSeedImporter` through `VocabRootSeedSync` (roots matched by track, normalized root and homograph in two passes, rows then parents; word rows by language and key; a local `manual` row is kept against a non-manual seed row; a seed root without a parent leaves a local parent alone). Data quality V1 (keys of one entry with different roots), V2 (root key missing in the lexicon, error), V3 (own key of a root belongs to another root) in `DqVocabRootChecks`, group "Vokabel-Wurzeln". The import preview did not exist for vocab: `GET api/maintainer/vocab/seed/import/preview` (dry run in a rolled-back transaction) feeds a line "Wurzeln: n neu, m geändert, k manuell behalten" on the vocab card of `/edit/imports`; n and m count roots and word rows together.

Confirmed 2026-11-27: simple words show their own root dimmed. Deeper families via `ParentRootId` (manual, AI fill deferred).
