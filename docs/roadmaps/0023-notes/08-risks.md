# 0023 · Risks worth naming before starting

- **Notes are the first irreplaceable user content in the app.** Everything else can be re-seeded; notes cannot. A seed rebase leaves the `Notes` table alone (no FK to `Elb1871Words`), but a fresh database (`compose.fresh.yml`, dropped volume) loses them unless exported first. Until 0023.6 there is no export, so rows 0023.1–0023.5 should only be used with test notes. Mitigation: export from 0023.6 on, the "Notizen" card shows the age of the newest export, `docs/deployment.md` says it in bold.
- **Word anchors drift silently without the quote check.** `Elb1871Words` ids are recreated by every rebase, and bulk replace or word splits move positions. Without `QuotedText` comparison a note about „lieben" would end up on „Gott" and nobody would notice. Mitigation: natural keys plus quote check from 0023.2, drifted notes fall back to verse level visibly.
- **German reference detection produces false links.** `Am`, `Ri`, `Hi`, `Ob`, `Mi` are everyday words or abbreviations. A note full of wrong links looks broken and sends readers to random chapters. Mitigation: verse-required rule and the test catalogue in 0023.3; links are computed on read, so a parser fix repairs old notes immediately.
- **Public notes teach under the app's name.** An approved public note is read by anonymous visitors as part of the study tool. The approval snapshot keeps edits from bypassing review; internal notes are visible to every logged-in user without review, which is the maintainer's explicit choice. The hide action and the admin log are the only moderation tools; if internal notes start being abused, the signal is hide actions on internal notes, and the fix is a per-user right to publish internally.
- **XSS through Markdown.** Notes are displayed to other users. MDXEditor renders through its own node model (no raw HTML), but links are the hole: `javascript:` and `data:` must never become anchors. Covered in 0023.3f with a test; no raw-HTML plugin may ever be added to the editor.
- **MDXEditor bundle weight.** It pulls in Lexical and the mdast toolchain (several hundred kB). Loaded for every reader it would slow the public reader that anonymous users depend on. Mitigation: lazy chunk for editor and view, loaded only when a chapter has notes or the user starts writing; measure in 0023.1f and 0023.4f.
- **Import resurrects deleted notes.** The import is an upsert without deletes, so a note deleted after the export comes back on re-import. Accepted and stated on the card; a tombstone list is the fix if users complain.
- **Deactivated authors.** Their internal/public notes stay visible with their name. Assumed acceptable (CC0, deactivation is not deletion); if a removal request comes, the maintainer hides the notes. A real account deletion with note removal is not part of this roadmap.
