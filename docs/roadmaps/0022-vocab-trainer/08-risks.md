# 0022 · Risks worth naming before starting

- **Derived meanings teach whatever the mappings say.** Most links are AI-made. A wrong or skewed rendering becomes an accepted answer and is drilled into the learner. Mitigations: the share and count thresholds, the "ungeprüft" badge, the derive report of changed top meanings, and the maintainer reviewing the top 300–500 per track first (80 % of the text). If learners report wrong meanings, the signal is to study only reviewed entries above a rank. That is one `WHERE` clause in the picker.
- **Elberfelder 2027 is still thin, so "2027 with 1871 fallback" is mostly Elb1871 today.** Revision words with `Change = 'changed'/'new'` have no German lemma and are counted by their form, which splits counts (`sprach` vs `sprechen`). Show the `FromRevision` share on the detail page. A lemma column on `RevisionWords` is a separate change when the share grows.
- **Lexicon edits change what a learner's card means.** The learner decides (keep or reset), but only if the change was recorded. An edit path that skips the `ContentVersion` bump changes the card silently. Every write in the editor API goes through one service method that bumps and logs, and 0022.4's tests check the bump per change type. Bulk jobs (derive, agent forms, seed import) must use the same path. A seed import that rewrites meanings without bumping would be the silent case.
- **Many small edits turn into notice fatigue.** A maintainer polishing the top 300 entries flags almost every card of an early learner several times. The list shows only the newest state per entry (all changes since the card's version, folded into one item) and has "Alle weiterlernen". If learners still complain, the signal is to bump only for accepted-meaning and typing-form changes.
- **A merge drops one of two cards.** Keeping the higher stability is a guess. The dropped card's review log stays, so the decision can be revisited, but the card itself is gone.
- **Rank shifts reorder the course.** Regeneration and key moves recompute ranks, so learners can find new words behind them. Picking takes "the lowest rank without a card", so nothing is lost, but expect "I learned word 400 but 380 is new" questions.
- **Hebrew frequency is the harder count.** Hebrew Strong's are per morpheme (`H9001/{H0559}`). Counting the main morpheme and excluding H9001–H9049 is the assumption here. Check the top 20 of the OT course by eye in 0022.1 before anything depends on the ranks.
- **Grouping by `OriginalWord` can merge homographs or split real lemmas.** Greek lemmas with spelling variants across entries end up as two entries. Hebrew homographs end up as one. The editor's key move is the repair tool. Count the multi-key entries after 0022.1 so the size of the manual review is known.
- **Garage is new production infrastructure.** Losing the volume loses every recording, and recordings are not in the seed (only the keys). The backup section in 0022.5 belongs in the same commit as the service. Without `ObjectStorage` config the app must run normally. 0022.5's "Done when" checks that.
- **0022.7 depends on an unpublished package.** If FsrsSharp v6 is not on NuGet when 0022.7 starts, everything up to 0022.6 can still ship. Do not add a temporary project reference to another repo: keeping the package behind `VocabScheduler` makes a later swap one file.
- **Four new dependencies need approval** (`AWSSDK.S3`, FsrsSharp, `@breezystack/lamejs`, `simple-keyboard`). Each is named in chat in its row, not added in bulk.
