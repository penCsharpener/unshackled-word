# Roadmap 0005: Mapping v2 (groups, provenance, review, revision layer)

## Goal

Today the Elberfelder 1871 ↔ Greek/Hebrew mapping is two edge tables, `Elb1871GreekMapping` (170,071 rows) and
`Elb1871HebrewMapping` (556,416 rows), one row per (`ElbWordId`, `StepWordId`). Everything else is encoded in
`NULL`s and flags: an added word is a row with `StepWordId NULL`, `IsAddedWord` and a `ParentGermanWordId`; "this
source word needs no German word" cannot be said at all; there is no author, no AI run, no confirmation, no history
(a save in the mapping editor deletes and re-inserts the verse, roadmap 0003), and the rows point at STEP's `SERIAL`
ids, which change when STEP is re-imported.

The data shows what the flags really carry (full copy of the dev DB, read-only, 2026-11-10):

- 32,995 Greek and 59,028 Hebrew rows have `IsAddedWord = TRUE`, but 624 / 49,852 of them also name a
  `StepWordId` (the importer and all readers already treat those as normal links).
- 5,906 / 1,597 rows are normal links that still carry a `ParentGermanWordId` (e.g. Mt 1:11 `die` → τῆς, parent
  `Zeit`); readers ignore the parent.
- Rows whose parent is in another verse: 53 / 179; parent = the word itself: 16 / 53 (of these, 32 / 112 and
  4 / 28 are real added-word rows without a `StepWordId`).
- `GermanWordPart`: 43,395 Hebrew + 65 Greek values are the whole word, 7 are `*`; only 4,204 Hebrew + 3 Greek
  values are real parts (`Schafhirten` → `Schaf` + `hirten`).
- One German word with several source words: 27 Greek / 2,878 Hebrew words; one source word with several German
  words: 8,067 / 174,125 source words (`Und die Erde` → וְהָאָרֶץ).
- Unmapped source words: 13,579 Greek (8,920 of them articles) and 11,378 Hebrew (4,070 object markers `HTo`).
- `CreatedAt` falls on 3 (Greek) and 5 (Hebrew) distinct days: it is the seed/AI-batch time, not a per-edit time.
- `StrongsNumber` (Greek only) is stale in 3,113 rows.
- No orphans: every `ElbWordId` and `StepWordId` exists.

This roadmap replaces the edge tables by a small group-based model with explicit kinds, provenance, a changeset
(proposal → review → merge) workflow, confirmations and hooks for the text revision layer; migrates the existing data
(validated on a full copy: 0 lost edges); and moves the editor, the readers, the seed and the AI worker over without
downtime, through compatibility views.

Drafts (validated, see "Validation"): `docs/drafts/mapping-v2-schema.sql` (DDL, comments, example queries) and
`docs/drafts/mapping-v2-migrate.sql` (data migration + verification queries). Their full text is embedded in
[Appendix A — Schema DDL](#appendix-a) and [Appendix B — Data migration](#appendix-b), generated byte for byte from the
drafts; the drafts stay the source, the appendices make this roadmap self-contained.

Out of scope (see "Deferred"): the text revision UI and slider, login/roles UI, further source editions, comment
threads, MCP write tools.

## Model

```
                     Users (human / ai / rule / system; contributor / reviewer / maintainer)
                       │ author                    │ reviewer
                       ▼                           ▼
AiRuns ─────────── Changesets ──────────────── ChangesetRemovals ──► (links/edits to end on merge)
(model, prompt,    draft→submitted→merged
 range, status)        │ │ rejected/withdrawn/superseded
                       │ └───────────────► GermanEdits (Level, RefId, From..To) ──► GermanEditWords (InheritsFromWordId)
                       ▼                                                                │
                  MappingLinks (Kind aligned|added|covered, Reason, Level, State, IsActive, Confidence)
                   │                         │                               ▲
                   ▼                         ▼                               │
   MappingLinkGermanWords            MappingLinkSourceWords          MappingConfirmations
   (BaseWordId | EditWordId,          (SourceWordId)                 (confirmed/disputed/retracted)
    PartIndex, Role core|added|grammar)      │
        │                                    ▼
        ▼                              SourceWords (stable id, ExternalId → StepGreekWords / StepHebrewWords)
   Elb1871Words (immutable base)             │
                                             ▼
                                       SourceTexts (step-tagnt, step-tahot, later SR GNT, BYZ, WLC)

Example Joh 1:1 (level 0):   [Im] ↔ [Ἐν]   [Anfang] ↔ [ἀρχῇ]   ...   covered/article: [ὁ] grammar→[Gott]
Example Gen 1:1:             [Im, Anfang] ↔ [בְּרֵאשִׁית]   covered/object_marker: [אֵת]   [Schaf|1] ↔ [רֹעֵה], [hirten|2] ↔ [צֹאן]
```

Why not the other way:

- **Keep edges, add columns (0002 S29 shape).** Cannot express "covered by grammar" without fake rows
  (`ElbWordId NULL` breaks `NOT NULL` and `UNIQUE NULLS NOT DISTINCT`), keeps `NULL`-encoded states, and history would
  need a second shadow table per language.
- **Edges plus a group id.** Two sources of truth for the same grouping; the editor already derives groups from edges
  (`computeGroups`), and the only thing edges add is the pairing inside n:m groups, which the AI data does not carry
  reliably (over-assignment).
- **One row per token with "state" (mapped/added/covered/unmapped).** A token can only be in one group, but groups
  are many-to-many; the group still needs its own table, and "unmapped" rows for 25k source words would have to be
  maintained on every STEP import.
- **Event sourcing (store diffs only, materialise the current state).** Most honest history, but every read needs the
  projection, and Dapper raw SQL becomes replay code. Immutable rows + lifecycle columns give the same history with
  plain `WHERE "IsActive"` reads.
- **`ValidFrom`/`ValidTo` ranges + `tstzrange` exclusion.** Time travel is not a requirement; lifecycle via
  changesets already orders changes, and the per-level uniqueness is simpler with partial unique indexes.
- **Point links at STEP ids (as today).** STEP `SERIAL` ids move on re-import; an FK would block the seeder. The
  registry costs 448k small rows (74 MB) and gives real FKs.
- **One table per language (as today).** Doubles every query and endpoint; `SourceTextId` + composite FK keeps
  Greek and Hebrew apart just as safely and makes further editions free.

## How to use this roadmap

Work in table order or as *Depends on* allows; one task = one commit; tick the box in the task's details when done.
Every slice runs end to end and keeps `dotnet build UnshackledWord.slnx`, `dotnet test` and, for `f` rows,
`docker compose run --rm --no-deps unshackledword.web bun run check` green. Backend rows come first inside a slice; the
`f` row of the same number is the frontend part of that slice. DB experiments: never write to the shared DB copy;
use a scratch database (`postgres-test-db`) or a throwaway container, see "Validation". Conventions of 0004
("Conventions for all steps") apply unchanged (Dapper only, `*Sql` constants in repo style, FakeDbReader tests,
design tokens, i18n de/en, `Components.md`, Bruno files updated in the slice that changes a contract).

## Background

### Why groups work on the existing data

Connected components of the legacy edge graph (German word/part ↔ STEP word) give 420,097 aligned links
(128,489 Greek, 291,608 Hebrew). Distribution: 238,217 groups 1:1, 119,633 2:1, 45,360 3:1, 11,559 4:1;
3,634 groups have ≥ 6 tokens, 198 have ≥ 10, the largest has 46 (over-assigned AI rows such as Joh 18:19 `Der` →
Ὁ, τὸν, τῶν, τῆς pull neighbours together; the editor needs "split group"). 200 groups span two German verses (link
`RefId` = the lower one). The compat views expand n:m groups as cross products: 80 Greek / 8,454 Hebrew pairs that
were not in the legacy tables; nothing is lost (V3 = 0, V9 missing = 0).

### Migration result (full copy, 2026-11-10, ~3.5 min)

Treatments per legacy row are in the header of `docs/drafts/mapping-v2-migrate.sql`. Added words: 31,753 / 8,228
attached to their parent's link, 363 / 52 via a chain of added parents, 98 / 283 German members in 86 / 195
free-standing `added` links. 157 / 613 added rows are dropped because the same word has an edge; 1 / 108 empty rows
are dropped. v2 tables incl. indexes ≈ 470 MB (legacy: 103 MB; `MappingLegacyRows` is 82 MB of that and can be
dropped after cut-over).

### Example queries (from the schema draft, measured on the full copy)

Q1 effective mapping of a verse 8.6 ms, Q2 unmapped source words of a range 0.9 ms, Q3 added words 1.5 ms, Q4 history
of a word 1.6 ms, Q5 effective mapping at a slider level 2.1 ms, Q6 covered words of a book 4.5 ms; compat view for
one verse 3–5 ms.

#### A.1 Header (model, identities), schema and extension

```sql
-- =====================================================================================================================
-- Mapping v2: Elberfelder 1871 (German) <-> Greek (NT) / Hebrew (OT) source words
-- Draft for roadmap 0005 (docs/roadmaps/0005-mapping-redesign.md). Target script name when it ships:
--   src/UnshackledWord.Tooling.Postgres.Migration/scripts/0009_MappingV2Schema.sql
-- (0007 stays reserved for 0002 S29 and is retired by this design, 0008 belongs to roadmap 0004.)
--
-- Postgres 18+. Only plain tables, CHECK/UNIQUE/FK constraints, a few partial indexes, one exclusion constraint
-- (btree_gist, trusted extension) and one generic append-only trigger. Dapper friendly: every table has an int "Id",
-- every state is a short varchar code with a CHECK (no Postgres ENUM types, so adding a code is a one-line ALTER).
-- The script is idempotent (IF NOT EXISTS / ON CONFLICT DO NOTHING) so it can be re-run outside DbUp.
--
-- ---------------------------------------------------------------------------------------------------------------------
-- MODEL IN ONE PARAGRAPH
-- ---------------------------------------------------------------------------------------------------------------------
-- A mapping is a set of LINKS. A link is one alignment unit: a SET of German tokens <-> a SET of source tokens of one
-- source text (TAGNT or TAHOT today). 1:1, 1:n, n:1, n:m and discontinuous phrases ("er ... ging" <-> ἦλθεν) are all
-- the same shape; only the member lists differ. Every link has a KIND:
--   aligned  - >= 1 source word and >= 1 German 'core' word. German words in the link with role 'added' are words the
--              translators added to render this phrase ("des" in "des Geschlechts" <-> γενέσεως).
--   added    - German words only (all role 'added'): additions that belong to no particular source phrase.
--   covered  - source words only, no German 'core' word: the source word needs no German word because German grammar
--              covers it (article, particle, object marker, person ending...). "Reason" says why; optional German
--              members with role 'grammar' point at the German word whose inflection/word order carries it.
-- "Unmapped" is NOT a state: it is the absence of any active link for the token. That keeps "not yet mapped" and
-- "deliberately has no counterpart" (covered / added) apart without a third NULL-ish row type.
--
-- Links are IMMUTABLE once written (trigger below). A change is a CHANGESET (proposal): it adds new links and lists
-- active links it removes. Many users write changesets; only a maintainer/reviewer merges them (Linux-style). Merging
-- flips the lifecycle columns: removed links 'active' -> 'superseded', new links 'proposed' -> 'active'. Nothing is
-- deleted, so the full history is the table itself. AI output is a changeset authored by an AI user and tied to an
-- AI_RUN (model, prompt version, scope). "Let AI redo this verse range" = a new AiRun for the range; its changeset
-- supersedes older open AI changesets of that range and, on merge, replaces only unconfirmed AI-authored links.
-- Human trust is a separate, append-only CONFIRMATION log per link (confirmed / disputed / retracted).
--
-- Text revisions: Elb1871Words stays the immutable base text (level 0). A GERMAN_EDIT replaces a span of base
-- positions of one verse with new tokens (GermanEditWords) at a slider LEVEL 1..10000. Links reference either base
-- tokens or edit tokens, and carry the level they belong to ("Level"). The effective mapping at slider level L is, per
-- token, the active link with the highest Level <= L whose German tokens are all visible at L. Base links therefore
-- stay valid forever; an edit word with "InheritsFromWordId" reuses the base word's links without a new link.
--
-- Identity of tokens:
--   German base token = "Elb1871Words"."Id" (real FK; the base text is seeded once and never rewritten).
--   Source token      = "SourceWords"."Id", our own stable registry row per STEP word. The seeder numbers STEP words
--                       1..n in Bible order, so a changed STEP release shifts ids; links never point at
--                       StepGreekWords/StepHebrewWords directly. "SourceWords"."ExternalId" is the current STEP id and
--                       is re-resolved by "SyncSourceWords" (verse + position + occurrence + MatchText, then n-th
--                       occurrence of the same text in the verse) after a STEP re-import.
--   Verse ids: German side uses Elb1871Words."HebRefId", source side uses STEP "LxxRefId" (book*1000000+chapter*1000+verse).
-- =====================================================================================================================

CREATE SCHEMA IF NOT EXISTS "unshackled-word";
CREATE EXTENSION IF NOT EXISTS btree_gist;   -- only for the GermanEdits exclusion constraint (int = inside GiST)


```

#### A.4 table `SourceWords`

```sql
-- Stable identity for every source token. ~448k rows (142,096 Greek + 305,652 Hebrew today).
-- Why a registry instead of pointing at STEP ids: StepDataBibleTextImporter numbers StepGreekWords/StepHebrewWords
-- 1..n in (LxxRefId, PositionInVerse) order (EnumerateWithIds). The ids are stable while the STEP file is unchanged,
-- but one inserted or removed word in a newer STEP release shifts every later id, and an FK to them would block the
-- re-import (same reason 0004 has no FK to STEP). Links get a real FK to this table; after a re-import
-- "SyncSourceWords" (below) re-resolves "ExternalId" by natural key (roadmap 0005.4). "MatchText" (STEP's
-- no-diacritics form) exists only for that re-match; it stays in the self-hoster's DB and is never exported.
-- "Occurrence" disambiguates the 75 (RefId, PositionInVerse) pairs that TAHOT has twice (e.g. 4026001 pos 1-3).
-- "RetiredAt": the STEP word is gone (removed, or its text changed). The row is never deleted (links keep their
-- history); it loses its "ExternalId" and its key no longer blocks the new word at the same position.
-- Position_UQ / External_UQ are DEFERRABLE INITIALLY IMMEDIATE: Postgres then checks them at the end of each
-- statement, not per row, so a re-match can shift the positions of a whole verse in one UPDATE. (They are no FK
```

#### A.8 5. GERMAN EDITS: table `GermanEdits` (+ 2 indexes)

```sql
-- =====================================================================================================================
-- 5. GERMAN EDITS (revision layer; designed now so links can reference edit tokens, implemented in a later roadmap)
-- =====================================================================================================================
-- An edit replaces base positions FromPosition..ToPosition (inclusive) of one German verse with 0..n new tokens.
--   replacement: ToPosition >= FromPosition, n >= 1        "erkannte" -> "verstand"
--   deletion:    ToPosition >= FromPosition, n = 0
--   insertion:   ToPosition = FromPosition - 1, n >= 1     new tokens go before base position FromPosition
-- Spans are always expressed against the immutable base positions (Elb1871Words."PositionInVerse"), never against
-- another edit, so edits at different levels compose without chains. Rule (service): a higher-level edit that
-- overlaps a lower-level one must cover the lower one's whole span; at slider level L the highest applicable level
-- wins. Lifecycle columns mirror MappingLinks (proposed/active/superseded/discarded via changesets).
CREATE TABLE IF NOT EXISTS "unshackled-word"."GermanEdits"
(
    "Id"                 INT GENERATED BY DEFAULT AS IDENTITY NOT NULL,
    "ChangesetId"        INT                                  NOT NULL,
    "VersionId"          SMALLINT                             NULL,      -- optional grouping (which named preset motivated it)
    "Level"              SMALLINT                             NOT NULL,
    "RefId"              INT                                  NOT NULL,  -- German verse (Elb1871Words."HebRefId")
    "FromPosition"       INT                                  NOT NULL,
    "ToPosition"         INT                                  NOT NULL,
    "Note"               TEXT COLLATE "und-x-icu"             NULL,
    "State"              VARCHAR(10)                          NOT NULL DEFAULT 'proposed',
    "IsActive"           BOOLEAN                              NOT NULL DEFAULT FALSE,
    "CreatedAt"          TIMESTAMP WITH TIME ZONE             NOT NULL DEFAULT now(),
    "ActivatedAt"        TIMESTAMP WITH TIME ZONE             NULL,
    "EndedAt"            TIMESTAMP WITH TIME ZONE             NULL,
    "EndedByChangesetId" INT                                  NULL,
    CONSTRAINT "GermanEdits_PK" PRIMARY KEY ("Id"),
    CONSTRAINT "GermanEdits_Changeset_FK" FOREIGN KEY ("ChangesetId") REFERENCES "unshackled-word"."Changesets" ("Id"),
    CONSTRAINT "GermanEdits_Version_FK" FOREIGN KEY ("VersionId") REFERENCES "unshackled-word"."GermanVersions" ("Id"),
    CONSTRAINT "GermanEdits_EndedBy_FK" FOREIGN KEY ("EndedByChangesetId") REFERENCES "unshackled-word"."Changesets" ("Id"),
    CONSTRAINT "GermanEdits_Level_CK" CHECK ("Level" BETWEEN 1 AND 10000),
    CONSTRAINT "GermanEdits_Span_CK" CHECK ("FromPosition" >= 1 AND "ToPosition" >= "FromPosition" - 1),
    CONSTRAINT "GermanEdits_State_CK" CHECK ("State" IN ('proposed', 'active', 'superseded', 'discarded')),
    CONSTRAINT "GermanEdits_IsActive_CK" CHECK ("IsActive" = ("State" = 'active')),
    CONSTRAINT "GermanEdits_Lifecycle_CK" CHECK (
        ("State" = 'proposed' AND "ActivatedAt" IS NULL AND "EndedAt" IS NULL)
            OR ("State" = 'active' AND "ActivatedAt" IS NOT NULL AND "EndedAt" IS NULL)
            OR ("State" = 'superseded' AND "ActivatedAt" IS NOT NULL AND "EndedAt" IS NOT NULL AND "EndedByChangesetId" IS NOT NULL)
            OR ("State" = 'discarded' AND "ActivatedAt" IS NULL AND "EndedAt" IS NOT NULL)),
    -- Invariant: two active edits of the same verse and level never overlap. Range type + exclusion is the only
    -- declarative way to say "no overlap"; half-open int4range(From, To+1) is empty for insertions, which overlap
    -- nothing (two insertions at the same point are ordered by "Id").
    CONSTRAINT "GermanEdits_NoOverlap_EX" EXCLUDE USING gist (
        "RefId" WITH =, "Level" WITH =, int4range("FromPosition", "ToPosition" + 1) WITH &&) WHERE ("IsActive")
);

CREATE INDEX IF NOT EXISTS "GermanEdits_Ref_IDX" ON "unshackled-word"."GermanEdits" ("RefId", "Level") WHERE "IsActive";
CREATE INDEX IF NOT EXISTS "GermanEdits_Changeset_IDX" ON "unshackled-word"."GermanEdits" ("ChangesetId");
```

#### A.10 6. LINKS and their members: table `MappingLinks` (+ 3 indexes)

```sql
-- =====================================================================================================================
-- 6. LINKS and their members (the mapping itself)
-- =====================================================================================================================
-- Cardinality: Link 1..n German members, 0..n source members (see Kind). Per slider level, a source word is in at most
-- ONE active link, and a German token part is in at most ONE active link as 'core' or 'added' (partial unique indexes
-- on the member tables). 'grammar' members may repeat ("Gott" carries the article ὁ and is also aligned to θεός).
--
-- Link lifecycle (columns State/IsActive/ActivatedAt/EndedAt/EndedByChangesetId are the ONLY mutable ones):
--   proposed --changeset merged--> active --a later merged changeset removes it--> superseded
--   proposed --changeset rejected/withdrawn/superseded--> discarded
--
-- "Level": 0 = link between base tokens (the Elb1871 mapping). > 0 = link that involves edit tokens of that level
-- (= max level of the edits whose tokens it contains). It is stored, not derived, because the uniqueness of
-- "one active link per token" holds per level: at level 1000 "Er sagte" <-> εἶπεν may coexist with the level-0
-- "Er sprach" <-> εἶπεν. The effective mapping at slider level L picks, per token, the highest Level <= L.
--
-- AI suggestion vs human: who wrote a link = its changeset's author (AiRunId set => machine). Whether a human
-- confirmed it = MappingConfirmations. Both are orthogonal to the lifecycle: an active link can be an unconfirmed AI
-- suggestion (all legacy data after migration), a proposed link can be a human's unmerged suggestion.
CREATE TABLE IF NOT EXISTS "unshackled-word"."MappingLinks"
(
    "Id"                 INT GENERATED BY DEFAULT AS IDENTITY NOT NULL,
    "ChangesetId"        INT                                  NOT NULL,
    "SourceTextId"       SMALLINT                             NOT NULL,
    "RefId"              INT                                  NOT NULL,   -- German verse of the link (Elb1871Words."HebRefId"); 200 legacy groups span two verses: lowest wins
    "Level"              SMALLINT                             NOT NULL DEFAULT 0,
    "Kind"               VARCHAR(8)                           NOT NULL,
    "Reason"             VARCHAR(24)                          NULL,
    "Confidence"         NUMERIC(4, 3)                        NULL,       -- AI self-reported 0..1; NULL for humans and legacy
    "Note"               TEXT COLLATE "und-x-icu"             NULL,
    "State"              VARCHAR(10)                          NOT NULL DEFAULT 'proposed',
    "IsActive"           BOOLEAN                              NOT NULL DEFAULT FALSE,
    "CreatedAt"          TIMESTAMP WITH TIME ZONE             NOT NULL DEFAULT now(),
    "ActivatedAt"        TIMESTAMP WITH TIME ZONE             NULL,
    "EndedAt"            TIMESTAMP WITH TIME ZONE             NULL,
    "EndedByChangesetId" INT                                  NULL,
    CONSTRAINT "MappingLinks_PK" PRIMARY KEY ("Id"),
    CONSTRAINT "MappingLinks_Changeset_FK" FOREIGN KEY ("ChangesetId") REFERENCES "unshackled-word"."Changesets" ("Id"),
    CONSTRAINT "MappingLinks_SourceText_FK" FOREIGN KEY ("SourceTextId") REFERENCES "unshackled-word"."SourceTexts" ("Id"),
    CONSTRAINT "MappingLinks_EndedBy_FK" FOREIGN KEY ("EndedByChangesetId") REFERENCES "unshackled-word"."Changesets" ("Id"),
    CONSTRAINT "MappingLinks_Level_CK" CHECK ("Level" BETWEEN 0 AND 10000),
    CONSTRAINT "MappingLinks_Kind_CK" CHECK ("Kind" IN ('aligned', 'added', 'covered')),
    -- Reason vocabulary per kind. covered: why the source word has no German word of its own.
    -- 'textual_variant' = the word is not in the edition the German follows (e.g. TR-only word, Elb1871 follows
    -- another reading); 'untranslated' = translator left it out (δέ, μέν). added: why the German word was added.
    -- ("Reason" IS NOT NULL is needed: NULL IN (...) is NULL, and a CHECK that yields NULL passes.)
    CONSTRAINT "MappingLinks_Reason_CK" CHECK (
        ("Kind" = 'aligned' AND "Reason" IS NULL)
            OR ("Kind" = 'covered' AND "Reason" IS NOT NULL AND "Reason" IN ('article', 'particle', 'conjunction', 'object_marker', 'inflection',
                                                    'pronoun_in_verb', 'preposition_in_case', 'idiom', 'textual_variant',
                                                    'untranslated', 'other'))
            OR ("Kind" = 'added' AND ("Reason" IS NULL OR "Reason" IN ('article', 'auxiliary', 'pronoun', 'clarification',
                                                                      'idiom', 'punctuation', 'other')))),
    CONSTRAINT "MappingLinks_Confidence_CK" CHECK ("Confidence" IS NULL OR "Confidence" BETWEEN 0 AND 1),
    CONSTRAINT "MappingLinks_State_CK" CHECK ("State" IN ('proposed', 'active', 'superseded', 'discarded')),
    CONSTRAINT "MappingLinks_IsActive_CK" CHECK ("IsActive" = ("State" = 'active')),
    CONSTRAINT "MappingLinks_Lifecycle_CK" CHECK (
        ("State" = 'proposed' AND "ActivatedAt" IS NULL AND "EndedAt" IS NULL)
            OR ("State" = 'active' AND "ActivatedAt" IS NOT NULL AND "EndedAt" IS NULL)
            OR ("State" = 'superseded' AND "ActivatedAt" IS NOT NULL AND "EndedAt" IS NOT NULL AND "EndedByChangesetId" IS NOT NULL)
            OR ("State" = 'discarded' AND "ActivatedAt" IS NULL AND "EndedAt" IS NOT NULL)),
    -- Targets of the composite FKs from the member tables. They copy (Level, IsActive[, SourceTextId]) and get them
    -- updated by ON UPDATE CASCADE, so the per-level partial unique indexes on members always see the link's state.
    CONSTRAINT "MappingLinks_IdLevelActive_UQ" UNIQUE ("Id", "Level", "IsActive"),
    CONSTRAINT "MappingLinks_IdTextLevelActive_UQ" UNIQUE ("Id", "SourceTextId", "Level", "IsActive")
);
```

#### A.16 9. APPEND-ONLY GUARD: function `GuardAppendOnly` (+ 14 triggers)

```sql
-- =====================================================================================================================
-- 9. APPEND-ONLY GUARD
-- =====================================================================================================================
-- History is only trustworthy if content cannot be rewritten. The trigger rejects DELETE, TRUNCATE and any UPDATE
-- that changes a column not listed in the trigger arguments. (to_jsonb(row) - text[] removes the allowed keys before
-- comparing.) TRUNCATE fires no row triggers, hence the extra statement triggers; they also stop
-- "TRUNCATE Elb1871Words CASCADE" from wiping the mapping through the member FK.
-- Escape hatch for scratch DBs/tests only: SET unshackled_word.allow_delete = 'on' (session) permits DELETE/TRUNCATE.
CREATE OR REPLACE FUNCTION "unshackled-word"."GuardAppendOnly"() RETURNS trigger
    LANGUAGE plpgsql AS
$$
BEGIN
    IF TG_OP IN ('DELETE', 'TRUNCATE') THEN
        IF current_setting('unshackled_word.allow_delete', TRUE) = 'on' THEN
            RETURN OLD;
        END IF;
        RAISE EXCEPTION '% is append-only: % not allowed', TG_TABLE_NAME, TG_OP;
    END IF;
    -- COALESCE: without trigger arguments TG_ARGV may be NULL, and jsonb - NULL would hide every change.
    IF (to_jsonb(OLD) - COALESCE(TG_ARGV, '{}'::text[])) IS DISTINCT FROM (to_jsonb(NEW) - COALESCE(TG_ARGV, '{}'::text[])) THEN
        RAISE EXCEPTION '% is append-only: only % may change', TG_TABLE_NAME, COALESCE(TG_ARGV, '{}'::text[]);
    END IF;
    RETURN NEW;
END;
$$;

CREATE OR REPLACE TRIGGER "MappingLinks_AppendOnly_TR"
```

#### A.17 9a. SOURCE WORD SYNC: function `SyncSourceWords`

```sql
-- =====================================================================================================================
-- 9a. SOURCE WORD SYNC (registry fill and re-match after a STEP re-import)
-- =====================================================================================================================
-- One function for the first fill (migration step 1), the SeedDb SourceWordRegistryRunner (roadmap 0005.4) and every
-- later STEP re-import. Idempotent; on an unchanged STEP import it changes nothing. Per source text:
--   pass 1  exact: same verse, position, occurrence and MatchText      -> keep (re-point "ExternalId" if the id moved)
--   pass 2  shifted: same verse and MatchText, n-th occurrence of that text in the verse among the rows pass 1 left
--           (a word inserted or removed earlier in the verse shifts positions, the text sequence stays)
--   rest    registry rows without a match are retired (word removed or text changed); STEP words without a match
--           get a new registry row. Links on retired words stay as they are and are reported ("ActiveLinksOnRetired"),
--           the maintainer re-maps them (the old model pointed such rows silently at the next word).
-- Usage: SELECT * FROM "unshackled-word"."SyncSourceWords"(1::smallint);   -- 1 = TAGNT, 2 = TAHOT
CREATE OR REPLACE FUNCTION "unshackled-word"."SyncSourceWords"(p_source_text_id SMALLINT)
    RETURNS TABLE ("SourceTextId" SMALLINT, "Exact" INT, "Shifted" INT, "Retired" INT, "Inserted" INT, "ActiveLinksOnRetired" INT)
    LANGUAGE plpgsql AS
$$
#variable_conflict use_column
DECLARE
    v_exact    INT;
    v_shifted  INT;
    v_retired  INT;
    v_inserted INT;
    v_links    INT;
BEGIN
    DROP TABLE IF EXISTS sync_cur;
    DROP TABLE IF EXISTS sync_match;

    CREATE TEMP TABLE sync_cur AS
    SELECT x.ext_id
         , x.ref_id
         , x.pos
         , row_number() OVER (PARTITION BY x.ref_id, x.pos ORDER BY x.ext_id)::smallint AS occ
         , x.match_text
    FROM (SELECT sgw."Id" AS ext_id, sgw."LxxRefId" AS ref_id, sgw."PositionInVerse" AS pos, sgw."GreekNoDiacritics" AS match_text
          FROM "unshackled-word"."StepGreekWords" sgw
          WHERE p_source_text_id = 1
          UNION ALL
          SELECT shw."Id", shw."LxxRefId", shw."PositionInVerse", shw."HebrewNoDiacritics"
          FROM "unshackled-word"."StepHebrewWords" shw
          WHERE p_source_text_id = 2) x;
    CREATE UNIQUE INDEX ON sync_cur (ext_id);
    ANALYZE sync_cur;

    CREATE TEMP TABLE sync_match (sw_id INT NOT NULL, ext_id INT NOT NULL, pos INT NOT NULL, occ SMALLINT NOT NULL);

    INSERT INTO sync_match (sw_id, ext_id, pos, occ)
    SELECT sw."Id", c.ext_id, c.pos, c.occ
    FROM "unshackled-word"."SourceWords" sw
        JOIN sync_cur c ON c.ref_id = sw."RefId" AND c.pos = sw."PositionInVerse" AND c.occ = sw."Occurrence" AND c.match_text = sw."MatchText"
    WHERE 1=1
        AND sw."SourceTextId" = p_source_text_id
        AND sw."RetiredAt" IS NULL;
    GET DIAGNOSTICS v_exact = ROW_COUNT;
    CREATE UNIQUE INDEX ON sync_match (sw_id);
    CREATE UNIQUE INDEX ON sync_match (ext_id);
    ANALYZE sync_match;

    INSERT INTO sync_match (sw_id, ext_id, pos, occ)
    SELECT r.sw_id, c.ext_id, c.pos, c.occ
    FROM (SELECT sw."Id" AS sw_id
               , sw."RefId"
               , sw."MatchText"
               , row_number() OVER (PARTITION BY sw."RefId", sw."MatchText" ORDER BY sw."PositionInVerse", sw."Occurrence") AS rn
          FROM "unshackled-word"."SourceWords" sw
          WHERE 1=1
              AND sw."SourceTextId" = p_source_text_id
              AND sw."RetiredAt" IS NULL
              AND NOT EXISTS (SELECT 1 FROM sync_match m WHERE m.sw_id = sw."Id")) r
        JOIN (SELECT cu.*
                   , row_number() OVER (PARTITION BY cu.ref_id, cu.match_text ORDER BY cu.pos, cu.occ) AS rn
              FROM sync_cur cu
              WHERE NOT EXISTS (SELECT 1 FROM sync_match m WHERE m.ext_id = cu.ext_id)) c
            ON c.ref_id = r."RefId" AND c.match_text = r."MatchText" AND c.rn = r.rn;
    GET DIAGNOSTICS v_shifted = ROW_COUNT;

    UPDATE "unshackled-word"."SourceWords" sw
    SET "ExternalId" = NULL
      , "RetiredAt"  = now()
    WHERE 1=1
        AND sw."SourceTextId" = p_source_text_id
        AND sw."RetiredAt" IS NULL
        AND NOT EXISTS (SELECT 1 FROM sync_match m WHERE m.sw_id = sw."Id");
    GET DIAGNOSTICS v_retired = ROW_COUNT;

    UPDATE "unshackled-word"."SourceWords" sw
    SET "ExternalId"      = m.ext_id
      , "PositionInVerse" = m.pos
      , "Occurrence"      = m.occ
    FROM sync_match m
    WHERE 1=1
        AND m.sw_id = sw."Id"
        AND (sw."ExternalId", sw."PositionInVerse", sw."Occurrence") IS DISTINCT FROM (m.ext_id, m.pos, m.occ);

    INSERT INTO "unshackled-word"."SourceWords" ("SourceTextId", "RefId", "PositionInVerse", "Occurrence", "ExternalId", "MatchText")
    SELECT p_source_text_id, c.ref_id, c.pos, c.occ, c.ext_id, c.match_text
    FROM sync_cur c
    WHERE NOT EXISTS (SELECT 1 FROM sync_match m WHERE m.ext_id = c.ext_id)
    ORDER BY c.ext_id;
    GET DIAGNOSTICS v_inserted = ROW_COUNT;

    SELECT count(*)::int
    INTO v_links
    FROM "unshackled-word"."MappingLinkSourceWords" ms
        JOIN "unshackled-word"."SourceWords" sw ON sw."Id" = ms."SourceWordId"
    WHERE 1=1
        AND ms."IsActive"
        AND sw."SourceTextId" = p_source_text_id
        AND sw."RetiredAt" IS NOT NULL;

    DROP TABLE sync_cur;
    DROP TABLE sync_match;

    RETURN QUERY SELECT p_source_text_id, v_exact, v_shifted, v_retired, v_inserted, v_links;
END;
$$;


```

```sql
-- =====================================================================================================================
-- Mapping v2: migrate legacy Elb1871GreekMapping / Elb1871HebrewMapping into the v2 tables
-- Draft for roadmap 0005. Target script name: scripts/0010_MappingV2Migrate.sql (runs after 0009_MappingV2Schema.sql).
-- Requires docs/drafts/mapping-v2-schema.sql to be applied. Legacy tables are only READ, never changed.
--
-- Idempotent: every write is skipped when "MappingLegacyRows" already has rows (temp table mig_guard), except the
-- SourceWords sync ("SyncSourceWords" from the schema script), which is idempotent by itself and also re-matches
-- after a STEP re-import. On a fresh install the migration scripts run before the seed, so this script is a no-op
-- there; SeedDb runs the same SQL after the legacy mapping import (roadmap 0005.3).
-- DbUp (Tooling.Postgres.Migration/Worker.cs) runs without a DbUp transaction and with the default 30 s command
-- timeout, so the script's own BEGIN/COMMIT stays, Worker.cs needs .WithExecutionTimeout(...) (roadmap 0005.2), and
-- the verification block moves out of the shipped script into the roadmap step (it only reads).
-- Runtime on a full copy of the dev DB (726,487 legacy rows, postgres:18 container): ~3.5 minutes including the
-- verification block; the component labelling loop (13 rounds) is the largest part.
--
-- ---------------------------------------------------------------------------------------------------------------------
-- HOW LEGACY ROWS BECOME LINKS
-- ---------------------------------------------------------------------------------------------------------------------
-- Legacy row = one edge (ElbWordId, StepWordId) or one "added word" row (StepWordId NULL, IsAddedWord, Parent...).
-- 1. Every row with a StepWordId is an EDGE between a German node (word, part) and a source node (SourceWords row).
--    German "part" = GermanWordPart when it is a real part of the word; whole-word copies and '*' count as whole word.
-- 2. Connected components of the edge graph become 'aligned' links. That is the only lossless grouping under the v2
--    invariant "a source word is in at most one active link" ("Und die Erde" -> וְהָאָרֶץ = one 3:1 link).
--    Measured on the DB copy: 419,739 components, 3,634 with >= 6 tokens, 198 with >= 10, largest 46 (over-assigned
--    AI rows such as Joh 18:19 "Der" -> Ὁ, τὸν, τῶν, τῆς chain neighbouring words together); 200 span two German verses.
-- 3. Added-word rows (StepWordId NULL, IsAddedWord) join the component of their parent as role 'added'. When the
--    parent has no component itself, the chain of added parents is followed (max 20 steps). When no component is
--    reached, or the parent is missing / the word itself / in another verse, the added words form an 'added' link per
--    chain root.
-- 4. Every legacy row gets one "MappingLegacyRows" entry with its link and a treatment code. Counts are Greek / Hebrew
--    rows from the run on a full copy of the dev DB (2026-11-10):
--      link                          edge, kept as is (131,169 / 495,683)
--      link_added_flag_ignored       IsAddedWord = TRUE but a StepWordId is set (624 / 49,852): treated as a normal core
--                                    link, exactly as AiMappingImportRunner and the readers do today
--      link_parent_dropped           IsAddedWord = FALSE with a parent and a StepWordId (5,906 / 1,597): parent ignored
--      added_attached                added word inside its parent's link (31,753 / 8,228)
--      added_attached_via_chain      parent was itself an added word; attached to an ancestor's link (363 / 52)
--      added_standalone_no_parent    IsAddedWord without parent (50 / 26)
--      added_standalone_parent_self  parent = the word itself (4 / 28)
--      added_standalone_parent_other_verse  parent in another verse (32 / 112)
--      added_standalone_parent_unmapped     parent (chain) has no link (12 / 117)
--      added_dropped_word_has_link   the word also has edge rows (157 / 613); the edge wins
--      empty_row                     no StepWordId, not added (1 / 108): carries no information
--      orphan_word / orphan_step     ElbWordId or StepWordId does not exist (0 / 0)
--    Result: 128,489 aligned + 86 added Greek links, 291,608 aligned + 195 added Hebrew links; 0 lost edges;
--    unmapped source words unchanged (13,579 Greek / 11,378 Hebrew); v2 tables incl. indexes ~470 MB
--    (legacy mapping tables: 103 MB; MappingLegacyRows alone is 82 MB and may be dropped once the cut-over is done).
-- 5. Provenance: one AiRun + one merged Changeset per (language, day of CreatedAt) under user 2 'ai-legacy'
--    (Greek: 3 days, Hebrew: 5 days). A link's changeset is the run of its newest row. All links are 'active' and
--    unconfirmed (no confirmation rows): the legacy data is AI output or indistinguishable hand fixes.
--
-- ---------------------------------------------------------------------------------------------------------------------
-- DROPPED OR APPROXIMATED (deliberately)
-- ---------------------------------------------------------------------------------------------------------------------
-- * Pairing inside n:m groups: v2 stores set <-> set. A group of 2 German and 2 source words no longer says which
--   German word went with which source word. Compat views expand groups as cross products (more pairs than before).
-- * Parent of non-added rows (link_parent_dropped) and the IsAddedWord flag on rows that have a StepWordId.
-- * Parent pointer of standalone added words whose parent is in another verse or the word itself.
```

```sql
      UNION ALL
      SELECT 'hebrew'
           , 2::smallint
           , ehm."Id"
           , ehm."ElbWordId"
           , ehm."StepWordId"
           , coalesce(ehm."IsAddedWord", FALSE)
           , ehm."ParentGermanWordId"
           , nullif(btrim(ehm."GermanWordPart"), '')
           , ehm."CreatedAt"
      FROM "unshackled-word"."Elb1871HebrewMapping" ehm) r
    LEFT JOIN "unshackled-word"."Elb1871Words" ew ON ew."Id" = r.word_id

-- Edges: German node = word_id * 100 + part_index (parts are < 100), source node = -SourceWords.Id
CREATE TEMP TABLE mig_edge ON COMMIT DROP AS
SELECT e.*
     , e.word_id::bigint * 100 + e.part_index AS gnode
     , -e.source_word_id::bigint              AS snode
FROM (SELECT r.*
           , CASE
                 WHEN r.part_text IS NULL THEN 0
                 ELSE dense_rank() OVER (PARTITION BY r.lang, r.word_id, (r.part_text IS NULL)
                                         ORDER BY strpos(r.word_lower, lower(r.part_text)) = 0
                                                , strpos(r.word_lower, lower(r.part_text))
                                                , lower(r.part_text))
                 END::smallint AS part_index
      FROM mig_rows r
      WHERE 1=1
          AND r.word_exists
          AND r.source_word_id IS NOT NULL) e;

CREATE INDEX ON mig_edge (snode);
```

#### B.4 3. Connected components

```sql
-- ---------------------------------------------------------------------------------------------------------------------
-- 3. Connected components (min-label propagation; converges in ~13 rounds on real data)
-- ---------------------------------------------------------------------------------------------------------------------
CREATE TEMP TABLE mig_lbl ON COMMIT DROP AS
SELECT n, n AS l
FROM (SELECT gnode AS n FROM mig_edge UNION SELECT snode FROM mig_edge) x;

CREATE UNIQUE INDEX ON mig_lbl (n);
ANALYZE mig_lbl;

DO
$$
    DECLARE
        changed INT := 1;
        rounds  INT := 0;
    BEGIN
        WHILE changed > 0 LOOP
            rounds := rounds + 1;
            WITH nb AS (SELECT e.gnode AS n, min(ls.l) AS l FROM mig_edge e JOIN mig_lbl ls ON ls.n = e.snode GROUP BY e.gnode
                        UNION ALL
                        SELECT e.snode, min(lg.l) FROM mig_edge e JOIN mig_lbl lg ON lg.n = e.gnode GROUP BY e.snode)
               , best AS (SELECT n, min(l) AS l FROM nb GROUP BY n)
            UPDATE mig_lbl
            SET l = best.l
            FROM best
            WHERE 1=1
                AND mig_lbl.n = best.n
                AND best.l < mig_lbl.l;
            GET DIAGNOSTICS changed = ROW_COUNT;
            IF rounds > 200 THEN
                RAISE EXCEPTION 'component labelling did not converge';
            END IF;
        END LOOP;
        RAISE NOTICE 'components labelled in % rounds', rounds;
    END
$$;
```

#### B.7 6. Added words

```sql
-- ---------------------------------------------------------------------------------------------------------------------
-- 6. Added words: attach to the parent's (or an ancestor's) link, otherwise group per chain root
-- ---------------------------------------------------------------------------------------------------------------------
CREATE TEMP TABLE mig_added ON COMMIT DROP AS
SELECT r.lang
     , r.source_text_id
     , r.legacy_id
     , r.word_id
     , r.ref_id
     , r.parent_id
     , r.created_at
     , EXISTS (SELECT 1 FROM mig_word_comp wc WHERE wc.lang = r.lang AND wc.word_id = r.word_id) AS has_link
     , (r.parent_id IS NOT NULL AND r.parent_id <> r.word_id AND p."HebRefId" = r.ref_id)          AS valid_parent
     , CASE
           WHEN r.parent_id IS NULL THEN 'no_parent'
           WHEN r.parent_id = r.word_id THEN 'parent_self'
           WHEN p."Id" IS NULL OR p."HebRefId" <> r.ref_id THEN 'parent_other_verse'
           END AS parent_problem
FROM mig_rows r
    LEFT JOIN "unshackled-word"."Elb1871Words" p ON p."Id" = r.parent_id
WHERE 1=1
    AND r.word_exists
    AND r.step_id IS NULL
    AND r.is_added;

CREATE INDEX ON mig_added (lang, word_id);

CREATE TEMP TABLE mig_added_res ON COMMIT DROP AS
WITH RECURSIVE chain AS (SELECT a.lang, a.word_id AS start_word, a.word_id AS cur, 0 AS depth, ARRAY [a.word_id] AS path
                         FROM mig_added a
                         WHERE NOT a.has_link
                         UNION ALL
                         SELECT c.lang, c.start_word, a.parent_id, c.depth + 1, c.path || a.parent_id
                         FROM chain c
                             JOIN mig_added a ON a.lang = c.lang AND a.word_id = c.cur AND a.valid_parent
                         WHERE 1=1
                             AND c.depth < 20
                             AND NOT a.parent_id = ANY (c.path)
                             AND NOT EXISTS (SELECT 1 FROM mig_word_comp wc WHERE wc.lang = c.lang AND wc.word_id = c.cur))
   , final AS (SELECT DISTINCT ON (c.lang, c.start_word) c.lang, c.start_word, c.cur AS root_word, c.depth
               FROM chain c
               ORDER BY c.lang, c.start_word, c.depth DESC)
SELECT a.lang
     , a.source_text_id
     , a.legacy_id
     , a.word_id
     , a.ref_id
     , a.created_at
     , f.root_word
     , wc.link_id AS attach_link_id
     , CASE
           WHEN a.has_link THEN 'added_dropped_word_has_link'
           WHEN wc.link_id IS NOT NULL AND f.depth = 1 THEN 'added_attached'
           WHEN wc.link_id IS NOT NULL THEN 'added_attached_via_chain'
           WHEN a.parent_problem IS NOT NULL THEN 'added_standalone_' || a.parent_problem
           ELSE 'added_standalone_parent_unmapped'
           END AS treatment
FROM mig_added a
    LEFT JOIN final f ON f.lang = a.lang AND f.start_word = a.word_id
    LEFT JOIN mig_word_comp wc ON wc.lang = f.lang AND wc.word_id = f.root_word AND f.depth > 0;

CREATE TEMP TABLE mig_added_group ON COMMIT DROP AS
SELECT g.*
     , nextval(pg_get_serial_sequence('"unshackled-word"."MappingLinks"', 'Id'))::int AS link_id
FROM (SELECT ar.lang
           , ar.root_word
           , min(ar.source_text_id) AS source_text_id
           , min(ar.ref_id) AS ref_id
           , min(ar.created_at) AS created_at
           , (max(ar.created_at) AT TIME ZONE 'UTC')::date AS last_day
      FROM mig_added_res ar
      WHERE 1=1
          AND ar.treatment LIKE 'added_standalone%'
      GROUP BY ar.lang, ar.root_word
      ORDER BY min(ar.ref_id), ar.root_word) g;

```
