# 0015 · Risks

- **A missing proxy config puts every visitor into one bucket.** Behind the proxy, `RemoteIpAddress` is the proxy's address; with empty `ReverseProxy` lists all readers share 300 requests per minute and the site looks down under modest traffic. Mitigation: the production startup warning (0015.2) and the README step; check the log line after the first deploy with limiting on.
- **Trusting forwarded headers too widely lets anyone pick their IP.** If `KnownNetworks` covers networks a client can reach directly (or the port `7654` stays published to the internet), a caller sends a fresh `X-Forwarded-For` per request and is never limited. Keep the WebApi port reachable only from the proxy and list the narrowest network.
- **The general limit may be too low for real reading.** Hover cards fire one request each; a fast reader on a big chapter may approach 300/min. Watch the rejection warnings for the first days with a shortened IP that also has normal reads; raising `PermitLimit` is an env var change, no deploy.
- **Closing the tagger writes breaks the Blazor BibleTagger's saves.** After 0015.6 its mapping/grammar saves and backups fail with 401, and nobody may notice until someone opens it. It is obsolete, but if its grammar editing is still needed, port that function to the React app before 0015.6, or keep 0015.6 out until then.
- **`editingEnabled` changing meaning can hide the editor from maintainers.** If the role is not passed correctly into `GetVerseMapping`, maintainers see a read-only editor and conclude the setting is off. The 0015.5 service test covers the four combinations; check once in the browser as a maintainer.
- **20 login attempts per minute per IP is still brute-forceable over days.** Per-IP limits do not stop distributed guessing and say nothing per account. If rejection logs show sustained `auth` traffic, add a separate `Auth` tier config or per-account lockout; until then the strict tier is the only defence.
- **IPv6 /64 grouping and CGNAT can over- or under-limit.** Many mobile users behind one carrier IPv4 share a bucket; one host with a /48 can still rotate /64s. Accepted for a small site; revisit only if rejection logs show complaints or rotation.
- **Rejection logs contain personal data.** Even shortened IPs are personal data under GDPR. They go to the existing rolling log files only; keep the log retention short and mention it in the privacy notice when the site goes public.
