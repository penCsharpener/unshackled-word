## Status (2026-11-25)

Planned after interview, implementation started. This roadmap goes before 0026: migration `0049`, version 0.12.0 (0026 moved to 0050/0051 and 0.13.0).

**0027.1 (token loader, scorer, dry run) done, with these deviations and findings:**

- **Score formula:** the formula in [03-algorithm.md](03-algorithm.md#score) divides a sum of idf by a sum of idf², so a verse is not 1 with itself and a rarer shared word gives a *lower* score. Implemented as a real cosine with weight w(s) = idf(s): `base = Σ idf(s)² (s ∈ A∩B) / (‖A‖·‖B‖)`, each shared bigram x→y adds `PhraseWeight · (idf(x)² + idf(y)²)` to the numerator. Everything else (df per testament, stop list, set semantics, bigrams over the stop-word-free sequence, top-K with MinScore, inverted index) is as documented. Shared bigrams are found by merging the two verses' sorted bigram sets for candidates with at least two shared tokens, not by a separate bigram index (same result).
- **Golden pairs (defaults):** Mk 14:58 → 2 Cor 5:1 rank 6 (done). Acts 7:48 → Acts 17:24 rank 1 (phrase χειροποίητος ναός κατοικέω). **Heb 4:12 → Rev 2:12 rank 11** (0.117, tied to three decimals with rank 10 Lk 21:24), Rev 1:16 rank 34, Rev 19:15 rank 55: Heb 4:12 shares only δίστομος G1366 with them (μάχαιρα G3162 ≠ ῥομφαία G4501, τομώτερος ≠ ὀξύς), against a long verse full of rare words. Base Strong's (`--base-strongs`) makes it worse (rank 15); StopDfShare 0.005 gives rank 9 (Rev 1:16 rank 13) but removes חֶרֶב, the only shared word of Ps 149:6 → Prov 5:4. Ps 149:6 → Prov 5:4 is rank 385 at defaults: Prov 5:4 has פֶּה H6310H ("mouths"), Ps 149:6 פִּיפִיָּה H6374, so only חֶרֶב is shared. Defaults left as documented; to be decided in 0027.6.
- **Stop list at 2 %** includes H3068G (YHWH), H0430G (God), H3478 (Israel), G2316 (θεός); logged per run.
- **Verb:** `verse-similarity --dry-run [--show <ref>]... [--show-count n] [--base-strongs] [--stop-df-share x] [--top-k n] [--min-score x] [--phrase-weight x]`. References in STEP form (`Heb.4.12`, English counting = `LxxRefId`), dotted with German/English names (`Mk.14.58`, `Ps.149.6`) or German citation (`Mk 14,58`, Elberfelder counting via `Elb1871Verses`). Without `--dry-run` it refuses with exit code 2.

**0027.2 (migration, repository, rebuild service, writing verb, SeedDb gate) done, with these deviations and findings:**

- **Migration `0049_VerseSimilarity.sql`** as in [04-model.md](04-model.md) plus `COMMENT ON` lines; applied by DbUp, then a second time by psql without error. `MigrationsHealthCheck.ExpectedMigration` = 49.
- **Code:** DBOs `Domain/Models/Dbo/VerseSimilarity`, `IVerseSimilarityRepository` + `VerseSimilarityRebuildService` + `VerseSimilarityOptions` (section `VerseSimilarity`, in the appsettings of SeedDb and WebApi) in `Application/Features/VerseSimilarity`, `VerseSimilarityRepository` in `Infrastructure/VerseSimilarity`. The replace is one transaction: DELETE, `INSERT … SELECT FROM unnest(arrays)` in batches of 100k rows (timeout 900 s each), then the run row `succeeded` before the commit. Scores are rounded to 4 decimals; with the phrase bonus a score can exceed 1 (max 2.61).
- **Advisory lock:** session lock `pg_try_advisory_lock(270001, 1)` (`VerseSimilarityRepository.LockClass`/`RebuildLockKey`) on its own connection for the whole run; not acquired → result `Busy` (verb exit code 3; 409 in 0027.5). While holding it, runs left `running` by a crashed process are marked `failed` ("interrupted").
- **Verb:** `verse-similarity` without `--dry-run` rebuilds with the configured defaults and the same overrides; exit codes 0 succeeded, 1 failed (old pairs kept), 2 bad arguments, 3 busy. The dry run now also takes its defaults from config.
- **Dev DB (measured):** 914,983 pairs (OT 680,025 for 23,261 verses, NT 234,958 for 7,958 verses), 30,949 source verses, at most 30 rows per source, 192 stop words (OT 101, NT 91), no cross-testament pair. Duration 12.2 s and 14.9 s (two runs; scoring ~2.6 s, the write the rest), peak RSS 308 MB. A second run replaced all rows (only the new `RunId` left).
- **Pipeline gate, deviation in placement:** not inside `StepDataBibleTextImporter` but a new runner `VerseSimilarityRunner` right after `StepDataRelationshipImporter`, because the Hebrew tokens come from `StepHebrewWordsNormalized`, which that runner fills: on a fresh database a rebuild inside the word import would score an empty OT and the gate would then never fill it. The gate itself is the Greek-editions rule: rebuild only when this run inserted STEP words (Greek or Hebrew; `IStepHebrewWordsRepository.BulkInsertAsync` now returns the inserted count, both counts travel in the scoped `StepImportResult`) or `VerseSimilarities` is empty; otherwise it logs "verse similarity up to date, no rebuild". A failed rebuild is logged and does not stop the seed. Verified with a SeedDb run filtered (locally) to the word import, the normalization and this runner: it logged "verse similarity up to date" and `RunId` stayed 4; unit tests cover the three gate cases.

**0027.3 (read endpoints) done, with these deviations and findings:**

- **Endpoints:** `GET api/elberfelder/similarVerses/{bibleBookId}/{chapter}?limit=` (1–30, default 10; 400 for an unknown book/chapter/limit like `chapterCrossReferences`) and `GET api/elberfelder/similarVerses/verse/{hebRefId}` (30; 400 for a malformed id, 404 when `Elb1871Verses` has no such verse). Both `AllowAnonymous`, under the general anonymous rate limit like every other read. Contracts `Domain.WebApi/Elberfelder/GetSimilarVerses`, `IVerseSimilarityReadService`/`VerseSimilarityReadService`, `SimilarVerseMapper` and `VerseSimilarityExplainerCache` in `Application/Features/VerseSimilarity`, `GetPageAsync`/`GetRunAsync` on `VerseSimilarityRepository`, endpoint folders `Endpoints/Elberfelder/GetSimilarVerses` and `GetSimilarVersesOfVerse`, Bruno `api/unshackled-word/Elberfelder/GetSimilarVerses*.bru`. `StrongsLabel` gained `Transliteration`.
- **Deviation, explanations from a cached corpus instead of per-request token loads:** loading tokens for the source verses plus their targets would be about 5,000 verses for Psalm 119 and still needs df/idf of the whole testament. So the service caches, per `RunId` of the stored hits (each hit row carries it), the two testament corpora built with that run's parameters (`GetRunAsync`) and calls `VerseSimilarityScorer.Explain` per pair; lexicon labels are cached per run too. The first request that sees a new `RunId` replaces the entry (invalidation without polling). Each corpus is built on first use. Stale only if STEP words change without a rebuild, which the rebuild after the import rules out.
- **Resolution:** sources and targets go through `Elb1871Verses` (one LATERAL join; a STEP verse with two Elberfelder verses resolves to the one with the same number, else the lowest). Hits without an Elberfelder verse, the verse itself and duplicate targets are dropped (debug log with the count; none dropped on the dev DB). Ranks are not renumbered after a drop. Every Elberfelder verse of the chapter is returned, with `hits: []` when it has none; the dev DB has verses without hits (e.g. Num 17:16) but no chapter without any row.
- **Measured (dev DB, local Kestrel, warm unless noted):** cold first request builds the testament corpus: Heb 4 (NT) 0.69 s, Ps 119 (OT) 0.86 s; warm Heb 4 4–11 ms (70 KB), Ps 119 17–30 ms (778 KB), Gen 1 7–9 ms (203 KB), Mt 5 10 ms, Ps 78 12 ms. Heb 4:12: Rev 2:12 at rank 11 (shared δίστομος G1366, only in the verse endpoint, since the chapter default is 10); Acts 7:48 → Acts 17:24 rank 1 with phrase "χειροποίητος ναός κατοικέω".

**0027.4 (word positions, backend) done, with these deviations and findings:**

- **Contract:** each hit gets `targetPositions` (positions in the hit's Elb1871 verse) and `sourcePositions` (positions in the source verse for the Strong's shared with *this* hit), both ascending, distinct, 1-based `PositionInVerse`. Computed from the hit's explanation `shared` Strong's (phrase Strong's are a subset).
- **Query:** `IVerseSimilarityRepository.GetWordStrongsAsync` reads, for all source verses with hits and all kept targets of the request at once, `(HebRefId, PositionInVerse, Strongs)`: one Greek query (`Elb1871GreekMapping` → `StepGreekWords.DisambiguatedStrongs`) and one Hebrew query (`Elb1871HebrewMapping` → `StepHebrewWordsNormalizedToHebrewWords` → `StepHebrewWordsNormalized` with `IsRoot`, `StrongsNumber`, the same tokens as `VerseTokenRepository`), skipped when the page has no hits. Grouping in `SimilarVerseMapper.GroupWordStrongs`/`PositionsOf`.
- **Added words:** an added word (`IsAddedWord`, no step word of its own) takes the Strong's of its parent word's mapping, so "die mit Händen gemacht sind" is one rendering of χειροποίητος, not just "Händen".
- **Verified (dev DB, local WebApi):** Acts 7:48 → Acts 17:24 (rank 1, shared G5499 χειροποίητος, G3485 ναός, G2730 κατοικέω): target positions 24, 27–32 = "wohnt Tempeln, die mit Händen gemacht sind,"; source positions 4, 7–12 = "wohnt Wohnungen, die mit Händen gemacht sind,".
- **Cost (warm, local Kestrel):** Heb 4 21–32 ms (was 4–11), Ps 119 98–158 ms (was 17–30; 1,029 verses, the Hebrew query alone is ~43 ms because the planner scans `Elb1871HebrewMapping`), Gen 1 35–43 ms. Payload +10 to 15 %. Cold corpus build unchanged.
- **Tests:** `VerseSimilarityReadServiceTests` (positions per hit, one word read per request, empty, no read without hits).
