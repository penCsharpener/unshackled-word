# 0027 · Risks worth naming before starting

- **The compute estimate is unmeasured.** Dev-DB access was not available while planning; the "seconds to minutes, a few hundred MB" claim rests on corpus size and posting-list reasoning. 0027.1 measures it before any table exists. If a run takes over ~10 minutes, lower `StopDfShare` or cap posting lists before 0027.2.
- **Repetitive passages flood the lists.** Num 7 (twelve near-identical offering paragraphs), genealogies, the synoptic parallels and the tabernacle chapters (Ex 25–31 vs 35–40) will fill each other's top 30. They really are similar, so this is correct, but it can hide subtler hits. Mitigation if it bothers readers: a per-chapter cap on hits, decided after 0027.3f, not before.
- **Disambiguated Strong's can split or merge wrongly.** `H0430G` vs `H0430H` keeps "God" and "gods" apart (good), but a STEP disambiguation error separates verses that belong together. Using base numbers would raise recall and noise. Check the golden pairs with both variants in 0027.1 if a golden pair goes missing.
- **A misleading hit looks authoritative.** A ranked list beside TSK reads like a cross reference. The panel shows *why* a verse matched (shared words, phrases), never only a score, and the label says "ähnlich", not "Querverweis". Thematic parallels without shared vocabulary will never appear; that is expected, not a bug.
- **The rebuild replaces the whole table.** The swap is one transaction and a failed run leaves the old rows. A run started during a STEP re-import can read half-imported words: SeedDb runs the rebuild after the import, and the maintainer job takes the same advisory lock as the import.
- **Versification.** Pairs are stored by `LxxRefId` (STEP) and shown by `HebRefId`. Verses whose numbering differs (Psalm titles, Mal 4, Rom 16:25–27) can map to none or two Elb1871 verses. 0027.3 resolves through `Elb1871Verses` and drops unresolved hits; count them in the run log.
- **Numbering collision with 0026.** Migration 0051 and version 0.13.0 assume 0026 lands first. Whichever starts second renumbers before writing its migration.
