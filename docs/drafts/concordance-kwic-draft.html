Design note (draft)

  • Layout: every row is a 3-column grid 1fr | auto | 1fr, so the keyword's centre is always the page centre. Context before the keyword is right-aligned and grows upward; context after is left-aligned and grows downward. The original word sits directly above the German keyword. The reference sits at the far left, on the keyword line.
  • Mobile (< 40rem): the reference moves to its own line above the row, the text gets smaller, and each side is cut to 3 lines with a fade (the lines next to the keyword stay). The full verse is one tap away through the reference. Wide screens show all of the text.

Data / API changes

  • The API already returns one item per occurrence (Joh 1,1 = 3 items), so paging and totalItems stay per row.
  • Replace elbWords + verseText with before, keyword tokens ({text, matched}, covering the first to the last matched Elberfelder position, so a word in the gap like "bösen" can be included) and after. Alternatively return all verse tokens plus the matched positions.
  • Order: canon, chapter, verse, then position in the verse.

Open questions

  • Should there be a sort by the German rendering, or by the word before or after the keyword (classic KWIC)?
  • Should the original show the inflected form (current) or the lemma?
  • Should desktop also cut very long context? If so, after how many lines?
  • For Hebrew (RTL): the original goes above the German word, and the German context stays LTR. Is that OK?
  • Should other hits in the same verse (e.g. the 2nd and 3rd "Wort" in Joh 1,1) get a light mark?
